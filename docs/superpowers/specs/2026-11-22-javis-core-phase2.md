# 자비스 본체 2단계 설계서

상태: 승인됨(총괄+Codex, 2026-11-22)

## 1. 사용자가 확인할 결과

PC에서 `javis ask "/brain 회의 결정"`을 실행하면 관련 노트의 상대 경로와 일치한 문단을 바로 읽을 수 있다. `/note`로 제안한 메모는 승인한 뒤에만 inbox에 생긴다. 외부 Obsidian vault는 사용자가 지정한 파일 목록을 확인한 뒤 한 번 가져온다. 폰에서는 기존 웹 질의와 출처 회수에 더해 기록 검색과 메모 승인을 쓴다. HUD에서 일지와 승인 상태를 확인하고 음성 입출력은 각각 켤 수 있다.

기준은 [1단계 계약](2026-11-21-javis-core-phase1.md)과 [하네스 설계 §5.10](2026-11-20-harness-design.md)이다. 현재 `core/gateway.py`는 회수 규칙에 걸리지 않은 텍스트를 모두 `Engine.run(text)`에 보낸다. `ClaudeEngine`은 이를 구독 CLI의 stdin으로 보내고 WebSearch를 허용한다. 두뇌 경로에는 이 엔진을 주입하지 않는다. 웹 도구를 꺼도 모델 제공자는 프롬프트를 받기 때문이다.

## 2. 라우팅과 공개 범위

| 입력 | 처리기와 출력 범위 |
|---|---|
| 승인·거절·대기 목록, 기록 검색, 기존 출처 회수 | 인증한 채널에서 게이트웨이가 먼저 처리한다. 이 명령의 인자 오류도 로컬 안내로 끝낸다. |
| `/brain <검색어>` | PC에서만 두뇌를 검색한다. Telegram은 vault를 열기 전에 PC용 명령을 안내한다. |
| `/note <본문>` | 입력한 텍스트 그대로 새 노트를 제안한다. CLI 제안은 PC 전용, 허용된 Telegram 개인 채팅의 제안은 같은 채팅 또는 PC에서 결정할 수 있다. |
| `/web <질문>`, 기존 일반 질문 | research가 이번 질문만 1단계 웹 엔진에 넘긴다. 일반 질문의 기본 동작은 유지한다. |

`teams/`에는 고정 이름·설명·처리기를 등록한다. 전용 명령과 명시적 접두사를 일반 질문보다 먼저 해석하며, 접두사 본문은 한 번만 처리한다. 기존 자연어 출처 회수 규칙은 접두사 없는 질문에 적용한다. 알 수 없는 슬래시 명령, 빈 인자, 비활성 팀, 두뇌 검색 실패는 사용법이나 상태를 반환한다. 팀을 고르는 모델 호출이나 실패 뒤 웹 재시도는 없다.

두뇌에서 얻은 **본문·질문·제목·파일명·경로·요약**은 로컬 전용이다. 읽기 결과는 CLI로 직접 반환하고 일지에는 종류·시각·상태만 남긴다. 검색 결과, 노트 속 링크·명령·임베드, 웹 응답은 표시용 데이터로 끝난다. 어느 처리기도 결과 문자열을 다음 명령으로 다시 해석하지 않는다.

웹 엔진·검색 질의·Telegram 답장 및 전송 대기열·음성 공급자·FTS·오류 출력으로 로컬 전용 필드를 넘기지 않는다. 경계는 결과 종류와 허용 필드로 검사한다. `ask` 원문을 일괄 저장하는 현재 경로에 비공개 요청을 넣으면 안 된다. PC에서 사용자가 새로 입력한 일반 웹 질문은 외부에 전송된다는 점을 CLI 도움말에 표시한다.

## 3. 승인 한 건의 수명

1. 제안자는 허용된 작업 종류(`note.create`, `brain.import`)와 실행 인자를 검증한다. 사용자 전용 데이터 디렉터리의 SQLite에 임의 ID(암호학적 난수 128비트 이상), 소유자·허용 채널, 생성·만료 UTC, 상태, 변경 불가한 실행 내용과 그 해시를 저장한다. DB와 WAL을 포함한 디렉터리는 OS 권한으로 소유자만 읽고 쓸 수 있게 한다. 메모 본문과 가져오기 명세는 실행에 필요한 동안만 전용 테이블에 둔다. 일반 일지와 검색 인덱스에는 복사하지 않는다.
2. `javis pending`과 폰의 `승인 대기`는 해당 사용자가 결정할 수 있는 건만 보여 준다. 결정 전 PC에서는 종류·목적지·본문 또는 파일 목록·만료를 확인한다. 폰에는 그 채팅에서 제출한 메모의 요청 메시지 번호·종류·건수·만료·승인 ID만 보낸다. 외부 vault 가져오기는 PC 전용이다.
3. `javis approve <ID>` / `javis reject <ID>`, 폰의 `승인 <ID>` / `거절 <ID>`, HUD 버튼은 같은 결정 함수를 쓴다. ID는 작업을 찾는 값이다. CLI는 데이터 디렉터리 소유 OS 사용자, HUD는 §6의 로컬 세션, 폰은 설정된 개인 채팅과 그 소유 발신자(`from.id`)를 각각 확인한다. 전달 메시지·봇 발신·전사문·모델 출력에서 결정 명령을 받지 않는다. 인라인 버튼은 도입하지 않아 기존 `allowed_updates=["message"]`를 유지한다.
4. 결정 시 DB 트랜잭션에서 소유자·채널·작업 해시·`pending`·`현재 UTC < 생성 UTC + 24시간`을 검사한다. 조건부 갱신 한 번으로 승인 행을 `executing`으로 바꾸고 실행자 PID와 OS가 보고한 프로세스 시작 시각을 함께 저장한다. 한 행을 갱신하고 커밋한 실행자만 고정된 작업을 한 번 실행한다. 거절은 같은 조건으로 `rejected`, 시한에 닿은 건은 `expired`다. 만료는 목록을 열지 않아도 적용한다. 결정 요청에는 ID 외의 실행 인자를 받지 않는다.
5. 성공은 `done`, 확정 실패는 `failed`로 마감한다. 재시작 시 `executing` 행의 PID가 없거나 그 PID의 현재 프로세스 시작 시각이 저장값과 다를 때만 복구한다. 실행자가 살아 있거나 확인 권한이 없으면 행을 그대로 둔다. 복구는 작업을 다시 실행하지 않고 실제 생성 파일과 승인 명세를 PC에서 대조해 결과 미상 또는 부분 완료로 알린다. 재시도가 필요하면 남은 파일만 새로 제안한다. 종료된 건은 ID·결과만 보존하고 민감한 실행 내용은 정리한다.

Telegram 제안은 기존 `update_id:message.date` 처리 키로 중복을 막는다. 제안·안전한 답장 조각·기록을 같은 트랜잭션으로 저장하고 결정에도 처리 키와 결정 결과를 함께 남긴다. 현재 `_DeferredSave`는 기록 하나만 임시 보관하므로 부작용을 먼저 실행한 뒤 답장만 저장하는 방식으로 확장하지 않는다. 재수신은 저장한 결정/전송 상태에서 이어 간다. 마지막 조각 뒤 커서를 전진시키는 1단계 계약은 유지한다. 답장이 중복돼도 작업은 다시 실행되지 않는다.

## 4. 두뇌 읽기·쓰기·가져오기

- `brain/`만 `JAVIS_BRAIN_DIR`를 연다. 루트는 명시적으로 설정한 로컬 디렉터리이고 코드 저장소·일지 폴더와 겹칠 수 없다. 미설정·접근 불가라면 두뇌 기능만 중지한다. 루트에 `BRAIN.md`가 없으면 기본 정책에 따라 승인된 메모는 `javis/inbox/`에만, 가져오기는 사용자가 해당 요청에서 지정하고 승인한 목적지 아래에만 쓴다. `BRAIN.md`가 있으면 그 제한도 적용한다. 정책 파일을 읽거나 해석할 수 없거나 부재를 확인할 수 없으면 쓰기를 중지한다. 노트 속 지시로 권한을 넓힐 수 없다.
- 읽기는 숨김 폴더·링크를 제외한 일반 UTF-8 Markdown을 대상으로 한다. 검색어가 일치하는 제목과 문단 순으로 최대 5개를 돌려주고 동점은 상대 경로와 문단 순서로 정한다. 파일 크기·탐색량·발췌 길이를 제한하고 결과에 생략 여부를 표시한다. 일치 없음과 읽기 실패를 구분한다. 임베딩·클라우드 요약·상시 색인은 필요 없다.
- 메모 대상은 `javis/inbox/` 아래에서 서버가 정한 새 Markdown 파일 하나다. `javis brain import <src> --dest <상대경로>`는 명시한 외부 vault를 그때만 읽고 상대 경로 구조를 보존해 허용된 목적지에 복사한다. 자동 발견·동기화·원본 수정은 하지 않는다. 숨김·설정·제어 파일(`BRAIN.md` 포함), 첨부물, 링크·정션·재분석 지점과 특수 파일은 대상에서 제외한다.
- 가져오기 미리보기는 파일별 원본/대상 상대 경로, 크기, 내용 해시, 충돌로 건너뛸 파일과 총량을 확정한다. 원본·대상 루트가 겹치거나 목적지가 절대 경로, 상위 이동, 예약 이름 또는 OS 경로 별칭이면 거절한다. 건수·바이트 상한을 넘으면 범위를 줄이도록 안내한다. 실행 시 같은 루트·경로·파일임을 다시 확인하고 승인한 바이트만 복사한다. 변경·추가된 파일까지 묵시적으로 승인하지 않는다.
- 새 노트와 가져오기에 같은 생성 함수를 쓴다. 승인 시 루트의 실제 경로와 파일 식별자를 고정하고 실행 시 다시 확인한다. POSIX에서는 열린 부모 디렉터리의 `dir_fd`를 기준으로 링크를 따라가지 않고 경로 요소를 하나씩 연다.
- Windows에서는 표준 라이브러리로 원본과 대상 경로의 기존 구성 요소를 각각 `os.lstat`로 검사한다. 조상이나 파일이 링크이거나 `st_file_attributes & stat.FILE_ATTRIBUTE_REPARSE_POINT`가 참이면 거절한다(정션 포함). 원본이나 임시 파일을 연 직후 `os.path.realpath`가 해당 고정 루트 안인지 경로 요소 단위로 확인하고, 경로의 `st_ino`와 열린 파일의 `os.fstat` 결과의 `st_ino`가 일치하는지 확인한다. 게시 직후에도 대상의 실제 경로가 고정 루트 안의 승인된 목적지인지, 대상의 `st_ino`가 게시 전 임시 파일에서 기록한 값과 같은지 확인한다. 검사 실패는 해당 파일의 실패로 기록한다.
- 단일 사용자 PC에서 두뇌 폴더에 쓰는 주체는 사용자 자신이라고 가정한다. Windows에서 경로 검사와 열기·게시 사이에 조상이 교체될 수 있는 짧은 경쟁 구간은 수용한다. `ctypes`를 이용한 추가 보호는 선택 사항이다.
- 완성한 임시 파일을 같은 파일시스템에서 **대상이 없을 때만 원자적으로 게시**한다. Windows에서는 같은 디렉터리의 임시 파일을 `os.rename`으로 게시한다(대상이 있으면 실패). POSIX에서는 `os.link`로 새 이름을 만든다. 덮어쓰는 rename/replace·복사 모드와 존재 검사 후 일반 쓰기를 금한다. 동시 생성, 대소문자 충돌, 기존 빈 파일도 모두 건너뛴다. 오류 시 자신이 만든 임시 파일만 정리한다. 가져오기는 파일 단위로 완료·충돌·실패를 집계한다. 중간 실패 뒤 이미 게시된 파일을 지우거나 다시 쓰지 않는다.

## 5. 일지와 자유 회수 검색

`worklog/store.py`의 v1은 WAL을 쓰며 `records.kind`가 `ask|recall`로 제한되고 알 수 없는 버전은 거절한다. 순차 마이그레이션을 `BEGIN IMMEDIATE` 안에서 수행한다. 기존 ID·항목 순서·처리 키·전송 조각·커서를 보존한다. 전용 승인 테이블을 추가하고 새 로컬 작업을 기록할 때는 웹 질의와 구별되는 종류를 사용한다. `출처 <ID> [번호]`와 어제/방금 회수는 계속 성공한 웹 질의만 본다.

`javis search <검색어>`와 폰의 `기록 검색 <검색어>`는 성공한 웹 질의의 질문·항목 본문에서 단어를 찾는다. 결과는 기록 ID·날짜·질문 미리보기를 최신순(동시각은 ID 역순)으로 최대 20건 보여 준다. 출처는 그 ID로 회수한다. 회수·검색 요청 자체, 승인·비공개 활동·실패·전송 조각은 제외한다.

SQLite FTS5에 기존 웹 기록을 한 번 채우고 이후 웹 답 저장과 같은 트랜잭션에서 색인을 갱신한다. SQLite 3.34 이상에서 `trigram` 토크나이저를 사용할 수 있으면 조사 붙은 단어도 부분 문자열로 찾는다. 공백으로 나눈 검색어 중 세 글자 이상은 리터럴 구문으로 인용해 `MATCH`에 바인딩한다. 한두 글자는 같은 공개 검색 필드에 `instr(필드, ?)`를 적용한다. 예를 들어 `회의`로 `회의에서`를 찾을 수 있다. 여러 검색어는 모두 일치해야 한다.

FTS5가 있으나 `trigram`이 없으면 `unicode61` 단어 단위로 검색하고 조사 붙은 단어의 부분 일치가 제한된다고 안내한다. FTS5 자체가 없으면 검색만 사용 불가로 안내하고 기존 DB 열기·기록·출처 회수를 보장한다. 색인을 사용할 수 있게 되거나 토크나이저가 바뀌면 기존 기록으로 다시 구축한다. 빈 입력은 사용법, 일치 없음은 0건이다. 두 채널 모두 검색 처리 중 엔진과 외부 검색 호출은 0회다.

## 6. 로컬 HUD

`javis hud`는 명시적으로 시작해 `127.0.0.1`의 가용 포트 하나에만 바인딩한다. 실행한 터미널에 표시된 일회용 난수를 브라우저에 입력하면 짧은 수명의 세션을 발급한다. 난수는 URL·접근 로그에 남기지 않는다. 데이터 읽기와 승인 API 모두 세션이 필요하다. 종료·재시작하면 세션과 난수를 폐기한다.

- 모든 요청의 `Host`는 실제 리슨 주소와 포트에 정확히 일치해야 한다. 세션 쿠키는 `HttpOnly; SameSite=Strict`로 제한한다. 세션 생성도 같은 출처의 POST만 허용한다. 승인·거절 POST는 정확한 `Origin`과 세션에 묶인 CSRF 토큰을 모두 확인한 뒤 §3으로 넘긴다. 누락·불일치는 상태 변경 전에 거절한다. GET에는 부작용이 없다.
- 표준 라이브러리 HTTP 처리기는 고정 라우트와 패키지에 포함된 정적 자산만 제공한다. 디렉터리 목록·임의 파일 제공·CORS·외부 CDN은 끈다. 표시 값은 텍스트로 삽입하고 CSP로 외부 연결·프레임 삽입을 막는다. 응답은 캐시하지 않는다.
- 최근 일지, 팀별 사용 가능 상태, 대기 건의 미리보기와 승인/거절 결과를 표시한다. 충돌·만료 시 상태를 다시 읽는다. 간단한 3D 배경은 로컬 JS로 그리고 그래픽을 쓸 수 없어도 목록과 버튼이 동작한다.

## 7. 선택적 음성

패키지 `core/settings.toml`의 `[voice]` 기본값은 `enabled=false`, `tts=false`, `stt=false`다. 사용자 전용 데이터 폴더의 설정이 이를 덮어쓰며 재시작 때 적용한다. 방향별 스위치와 전체 스위치가 모두 켜져야 동작한다. off이면 공급자 생성·키 조회·음성 다운로드·합성·전사·파일 생성·전송이 모두 0회다. 텍스트 봇의 기존 폴링은 계속된다.

| 기능 | 공급자 계약과 채널 동작 |
|---|---|
| TTS | `synthesize(text) → Audio(bytes, media_type)`. 허용된 웹 답 텍스트에만 적용한다. CLI는 사용자 전용 폴더에 새 오디오 파일을 저장하고 Telegram은 텍스트 답장 뒤 지원 형식의 음성 파일을 보낸다. |
| STT | `transcribe(Audio) → text`. 허용 개인 채팅의 발신자·음성 형식·크기·길이를 확인한 뒤에만 다운로드한다. 전사문은 초안으로 돌려주고 사용자가 일반 텍스트로 질문을 보내게 한다. 음성만으로 승인이나 쓰기를 실행할 수 없다. |

방향별 공급자를 선택한다. `local` TTS는 설치된 오프라인 OS 음성 기능을 사용한다. `elevenlabs` 어댑터는 TTS/STT를 별개 기능으로 선언하고 필요한 방향에서만 `ELEVENLABS_API_KEY`와 합성용 `ELEVENLABS_VOICE_ID`를 읽는다. 외부 STT를 켜면 허용 채팅의 음성 원본이 해당 서비스로 간다는 점을 설정에 명시한다. 두뇌 검색 결과·승인 메시지·검색 기록은 합성하지 않는다. 지원하지 않는 OS/방향, 키 누락은 해당 방향의 설정 오류다. 공급자를 자동 전환하지 않는다.

외부 어댑터는 고정 HTTPS 호스트에만 연결하고 리디렉션을 거부한다. 시간·용량에 상한을 두고 실패는 설정·형식·시간 초과·공급자 오류로 구분한다. 오디오와 전사문은 처리 후 폐기하고 로그·일지·FTS에 넣지 않는다(CLI가 요청한 출력 파일 제외). 키·인증 URL·원시 오류는 자식 환경·응답에 싣지 않는다.

Telegram에서 전사 초안은 일회 전송하고 재전송 큐에 원문을 넣지 않는다. 선택적 음성은 처리 키로 시도를 먼저 기록하고 실패·중단 뒤 자동 재호출하지 않는다. 텍스트 전송과 커서 복구는 음성 실패와 독립적이다.

## 8. 구현 순서와 인수 기준

각 행은 테스트 포함 추가·삭제 합계 **400줄 이하 목표**인 한 작업이다. 예상 초과 시 저장/어댑터 또는 OS별 구현으로 다시 나눈다. 선행 번호는 합쳐진 계약을 뜻한다. 각 명세에 구현·테스트·패키징 경로를 명시하고 Windows에서는 Codex 작업자와 반대 팀 리뷰 절차를 따른다.
