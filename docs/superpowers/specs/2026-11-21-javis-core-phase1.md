# 자비스 본체 1단계 설계서

상태: 승인됨(총괄+Codex, 2026-11-21)

## 1. 사용자가 확인할 결과

폰에서 “오늘 Claude 관련 뉴스 3개 정리해줘”라고 보내면 PC가 번호를 붙여 요약과 출처를 답한다. 다음 날 PC를 다시 켜고 “어제 두 번째 뉴스 출처 뭐였지?”라고 물으면 **그때 화면에 표시한 2번 항목의 링크**를 돌려준다. 새 검색 결과로 어제의 답을 재구성하지 않는다.

`uv run javis ask "<질문>"`과 `uv run javis serve`는 같은 단일 사용자 게이트웨이를 쓴다. `uv run javis log [-n N]`은 최근 기록의 ID·시각·질문·상태를 보여 준다. 이번 단계는 텍스트 질의, 공개 웹 검색, 로컬 일지, 출처 회수까지다. HUD·음성·팀 라우팅·두뇌 접근·승인 흐름·다중 사용자·서비스 등록은 후속 단계로 둔다. [상위 하네스 설계서 §1](2026-11-20-harness-design.md)

## 2. 요청 한 건의 수명

1. 채널이 입력을 검사해 `Request(channel, text, processing_key?)`를 만든다. Telegram 처리 키는 `update_id`와 `message.date`(유닉스 초)를 합친 문자열 `"<update_id>:<date>"`다. 채팅 ID와 본문은 키에서 제외하며, 허용된 개인 채팅의 텍스트만 게이트웨이에 넘긴다.
2. `core/gateway.py`가 출처 재질문이면 일지를 조회한다. 일반 질문이면 `Engine.run(text) -> EngineResult`를 한 번 호출한다. 이전 질문·답·URL을 일반 질문 프롬프트에 넣지 않는다.
3. 게이트웨이가 결과를 저장한 뒤 채널에 답을 넘긴다. 두 채널 모두 같은 항목 배열에서 번호·본문·링크와 기록 ID를 출력한다. 회수 요청에는 참조한 원본 ID를 남긴다.
4. 저장 실패 시 CLI는 실패 종료하고 Telegram은 처리를 멈춰 해당 업데이트를 미확인 상태로 둔다. 일지에 없는 답을 성공으로 알리지 않는다.

### 일지와 프로세스 경계

`worklog/store.py`는 Python 3.12 표준 라이브러리의 SQLite를 쓴다. CLI와 봇이 동시에 써도 요청 한 건이 온전히 남고, 텔레그램 전송 상태와 다음 offset도 같은 DB 트랜잭션으로 갱신할 수 있다. JSONL 파일과 별도 커서 파일 간의 복구 절차가 필요 없어진다.

- 사용자 전용 데이터 디렉터리는 `JAVIS_DATA_DIR`로 지정한다. 기본값은 사용자 홈 아래 `.javis`다. 저장소 안을 가리키는 설정은 거부한다.
- 요청 한 건에 고유 ID, UTC 시각, 채널, 종류(일반/회수), 요청, 순서 있는 결과 항목, 상태, 엔진·요청 모델, 소요 시간을 저장한다. 결과 항목은 본문과 순서 있는 URL 목록이다. 회수에는 엔진 정보가 필요 없다.
- `ok | error | timeout | quota | denied`는 처리 결과다. 실패 사유는 정해진 코드만 남긴다. Telegram의 전송 여부와 다음 미전송 조각 번호는 별도 필드다. 봇 하나당 데이터 디렉터리 하나를 사용하고 Telegram 처리 키에 유일 제약을 둔다. 폴링 offset은 계속 숫자 `update_id`를 기준으로 계산한다.

## 3. 비대화형 Claude 호출과 출처

어댑터는 구독 로그인한 로컬 CLI를 신뢰한 실행 경로에서 찾는다. 요청마다 빈 임시 작업 디렉터리에서 새 프로세스를 시작한다. 아래는 고정 옵션의 표기다. 실제 호출은 인자 배열과 UTF-8 표준 입력을 사용하고 입력 후 EOF를 보낸다. 질문을 명령줄이나 셸 문자열에 끼워 넣지 않는다.

```text
claude -p --input-format text --output-format json --restricted --safe-mode --strict-mcp-config --permission-mode dontAsk --tools WebSearch --allowedTools WebSearch --no-session-persistence
```

- 애플리케이션의 고정 출력 지시문은 `--system-prompt`로 전달한다. `core/settings.toml`에 모델이 지정됐을 때만 `--model`을 추가한다. 기본값은 로그인한 CLI의 기본 모델이다. `--tools`는 제공할 내장 도구를 제한하고 `--allowedTools`는 그중 무인 실행을 허용한다. 공개 검색 하나로 시작한다.
- 설치판이 필수 옵션을 지원하지 않거나 구독 인증을 사용할 수 없으면 설정 오류로 끝낸다. 제한을 풀거나 API 키로 재시도하지 않는다. 옵션은 설치판의 도움말로 확인했고, 조합의 실제 동작은 §6에서 검증한다. [Claude CLI 옵션](https://code.claude.com/docs/en/cli-reference)
- stdout 전체를 JSON 객체 하나로 읽는다. 종료 코드 0, `type=result`, `subtype=success`, `is_error=false`를 모두 확인한 뒤 문자열 `result`를 읽는다. 세션 ID와 사용량 등 외피의 메타데이터는 답에 포함하지 않는다. [비대화형 출력 계약](https://code.claude.com/docs/en/headless)
- `result` 자체에는 아래 모양의 JSON 객체 하나를 요구한다. 항목은 1개 이상이고 각 본문은 비어 있지 않아야 한다. 코드 펜스·잘린 JSON·필드 타입 오류는 `error/invalid_output`이다. 본문에서 URL을 긁거나 오류 출력을 답으로 돌려주는 복구는 하지 않는다.

```json
{"items":[{"text":"첫 번째 뉴스 요약","sources":["https://example.org/news"]}]}
```

- 공개 자료를 인용한 항목은 해당 항목의 링크를 제공한다. URL은 호스트가 있는 절대 HTTP(S) 주소만 허용하고 사용자 정보·공백·제어 문자가 있으면 버린다. 한 항목 안에서 중복만 제거하고 원래 순서를 유지한다. 유효한 링크가 없으면 “기록된 출처 없음”을 표시한다. 링크는 모델이 제시한 인용이며 접근 가능성이나 사실 여부를 검증한 표시는 아니다.
- 제한 시간에는 자식 프로세스 트리를 종료·회수하고 `timeout`을 남긴다. 비정상 종료나 오류 외피에서 식별 가능한 사용 한도 신호만 `quota`로 분류한다. 나머지는 `error`다. 정상 답 본문의 단어로 한도를 판정하지 않는다. stdout/stderr 수집에 크기 상한을 두고 원문은 폐기한다.

## 4. 새 세션의 출처 회수

작은 로컬 규칙으로 “방금 그거 출처 다시”, “어제 두 번째 뉴스 출처 뭐였지?”와 명시형 `출처 <기록ID> [항목번호]`를 두 채널에서 받는다. 자유로운 과거 대화 검색은 후속 단계다.

- “방금”은 가장 최근의 성공한 일반 답을 고른다. “어제”는 PC 로컬 시간대의 전날에 생성된 성공한 일반 답을 찾는다. 단일 사용자이므로 두 채널의 기록을 함께 보며 회수 요청과 실패는 후보에서 제외한다.
- 날짜 후보가 여럿이면 ID와 질문 앞부분을 보여 주고 명시형 입력을 안내한다. 후보가 없거나 ID·번호가 틀리면 해당 사실을 알린다. 모호한 출처 재질문도 같은 안내로 끝낸다.
- 번호는 그 답에 표시한 1부터 시작하는 항목 번호다. 번호를 생략하면 항목별로 링크를 보여 준다. 저장된 빈 출처도 그대로 표시한다. 원본 ID 조회는 최근 20건이나 요약 길이에 제한받지 않으며 회수 과정에서 엔진과 네트워크를 호출하지 않는다.

## 5. Telegram 수신·전송과 비밀 관리

`channels/telegram/bot.py`는 표준 라이브러리 HTTP 클라이언트로 단일 폴러를 실행한다. `getUpdates`는 양의 long polling 시간과 그보다 긴 HTTP 제한 시간, `allowed_updates=["message"]`를 사용한다. 첫 실행은 offset을 생략한다. 응답 순서대로 한 건씩 완료하고 다음 호출에 마지막 완료 ID + 1을 넘겨 확인한다. 빈 응답도 정상이다. 서버의 미수신 업데이트 보존 시간은 최대 24시간이다. 오래된 커서(24시간 경과)는 생략해 장기 휴면 뒤 낮은 ID로 시작해도 누락을 피한다. [Telegram 업데이트 수신 규약](https://core.telegram.org/bots/api#getupdates)

| 경계 | 동작 |
|---|---|
| 입력 검사 | `chat.type=private`와 허용 chat ID를 본문 처리 전에 확인한다. 불허 시 본문·발신자·chat ID 없이 `denied`와 처리 키만 남기고 무응답으로 커서를 전진시킨다. 미지원 메시지도 건너뛴다. |
| 답장 | 엔진 결과와 전송할 조각을 먼저 함께 저장한다. `sendMessage`는 일반 텍스트로 순차 전송하고 링크 미리보기를 끈다. 조각은 4,000 UTF-16 단위 이내에서 문자 경계를 지킨다. 성공 응답마다 다음 조각 번호를 저장하고 마지막 성공과 커서 전진을 함께 커밋한다. |
| 재시작 | 폴링 전에 미완료 전송부터 이어 간다. 처리 키가 같으면 저장된 결과와 전송 상태를 재사용한다. 1주 이상 업데이트가 없다가 이전과 같은 `update_id`가 와도 `message.date`가 다르면 새 요청으로 처리한다. 결과 저장 전 중단되면 엔진이 다시 실행될 수 있고, 서버가 전송한 직후 로컬 저장 전에 끊기면 해당 조각이 중복될 수 있다. |
| 일시 장애 | 네트워크 오류·5xx에는 상한 있는 지수 백오프와 지터를 쓴다. 429는 응답의 `parameters.retry_after` 이상 기다린다. 요청 실패나 빈 폴링 응답으로 커서를 앞당기지 않는다. |
| 영구 장애 | HTTP 상태와 API의 `ok/error_code`를 함께 확인한다. 401, 폴러 충돌·기존 webhook(409)은 원인 코드만 알리고 중지한다. 전송 대상 차단(403)·해당 메시지의 영구 거절(400)은 전송 실패를 기록하고 커서를 전진시킨다. webhook을 자동 삭제하지 않는다. |

런타임에서 `serve`만 환경 변수 또는 사용자 로컬 `.env`에서 `JAVIS_TELEGRAM_TOKEN`과 `JAVIS_TELEGRAM_CHAT_ID`를 읽는다. 설정이 비었으면 폴링 전에 종료한다. Telegram은 고정 HTTPS 호스트에만 연결하고 리디렉션을 따르지 않는다. 토큰이 포함된 요청 URL, 예외 문자열, HTTP 본문·헤더를 일지·콘솔·답장에 싣지 않는다. 봇은 입력에 설정된 토큰 값이 있으면 엔진 호출 전에 거절한다. 출력에 그 값이 있으면 저장·전송 전에 고정 오류 문구로 바꾼다.

엔진 환경은 OS 실행·구독 로그인에 필요한 변수만 이름으로 허용한다. Telegram 설정, API 키, 공급자 전환 변수, 데이터 폴더 경로는 전달하지 않는다. 검색 결과 속 명령은 외부 데이터로 취급한다. 프롬프트 문구만으로 주입을 막을 수 없으므로 셸·파일·MCP·WebFetch 권한을 주지 않고 일지와 두뇌도 입력에서 제외한다. 현재 질문의 검색어는 외부로 갈 수 있다. 관리자가 강제한 훅·정책이 있는 설치에서는 총괄이 같은 권한 경계를 확인한 뒤 사용한다.

## 6. 구현 순서와 인수 기준

| 순서 | 작업과 변경 경로 | 다음 작업에 넘길 결과 |
|---|---|---|
| A | `worklog/`, 저장소 테스트 | 순서 있는 항목 저장·조회, 날짜/ID 검색, Telegram 처리 키·전송 상태·커서의 트랜잭션 계약. 새 프로세스와 동시 작성자로 검증한다. |
| B (A 이후) | `core/`, `pyproject.toml`, CLI·엔진 테스트 | `javis = "core.cli:main"`, wheel에 core/worklog 포함. ask/log, 회수 규칙, 엔진 어댑터까지 연결해 Telegram 없이 첫 왕복을 검증한다. |
| C (B 이후) | `channels/telegram/`, `core/cli.py`, `pyproject.toml`, 채널 테스트 | serve와 채널 패키징. 가짜 Bot API 서버에서 인증·분할·복구를 검증한다. |
| D (통합 후) | `README.md`, `.env.example` | 실행법, 설정 이름, 실패 시 조치와 아래 실측 절차를 문서화한다. 봇 생성·비밀 입력은 사용자가 한다. |

경로 소유권은 A의 worklog가 Codex, B·C의 core와 Telegram이 Claude다. Windows 구현은 Codex 작업자에게 각 spec의 변경 경로를 명시해 배정하고 Claude 리뷰어가 교차 검토한다. 테스트 경로는 작업별로 나눈다.

- 자동 게이트는 `uv run pytest -q`다. 임시 데이터 폴더와 가짜 엔진 프로세스로 인자·환경·stdin, 성공/오류 외피, 잘못된 본문, 링크 누락·중복, 인증 실패·시간 초과·한도를 확인한다.
- 날짜를 고정해 뉴스 3개를 저장한 뒤 새 프로세스에서 2번 URL이 처음 표시한 값과 일치하고 엔진 호출이 0회인지 검사한다. 최근 20건 밖의 ID, 날짜 중복, 반복 회수, 존재하지 않는 번호도 검사한다.
- 가짜 Telegram 서버로 불허 chat, 비텍스트, 빈 폴링, 429·5xx·401·409, 중복 업데이트와 조각 전송 중 재시작을 재현한다. 재전송 후 결과 행 수와 엔진 호출 수, 조각 순서, 커서를 확인한다. 주입 지시가 든 검색 결과와 가짜 비밀값을 사용해 허용 도구·자식 환경과 로그 노출도 검사한다.
- 가짜 시계로 첫 답장 뒤 업데이트 없이 1주를 보낸다. 같은 `update_id`와 다른 `message.date`로 두 번째 질문을 보내면 별도 결과가 저장되고 두 번째 질문의 답이 전송돼야 한다. 두 번째 업데이트를 그대로 다시 보내도 결과와 엔진 호출은 총 2건이고 추가 답장은 없어야 한다.
- **구현 후 총괄 실측**은 구독 로그인 상태에서 CLI 뉴스 질의 → 번호별 링크와 일지 확인 → 새 프로세스에서 같은 링크 회수 순서다. 사용자 설정 후 휴대폰에서도 1회 왕복하고 봇을 재시작해 출처를 다시 받는다. 자동 테스트와 실측 결과를 구분해 기록한다.
